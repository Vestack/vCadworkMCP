# Runtime dependency of the MCP server (main.py).
# Upper bound is load-bearing: mcp 2.0 removed mcp.server.fastmcp, which
# main.py and core/server.py import. Lifting it means migrating to the 2.x API.
mcp>=1.6,<2

# Type stubs for the Cadwork API: element_controller, geometry_controller,
# attribute_controller, cadwork and friends. Cadwork provides the real modules;
# these stubs let mypy check the handler call sites, and let them be imported
# outside Cadwork.
#
# KEEP THIS MAJOR VERSION EQUAL TO THE CADWORK VERSION YOU TARGET. Checking
# against the wrong one is worse than not checking, in both directions.
#
# This machine has two Cadwork installations: v30 from 2024 (EXE_30,
# userprofil_30) and 33.0 "2026 BETA" (EXE_2026, userprofil_2026). PyPI has no
# 33.x stubs, so the pin below gives a clean baseline against v30 (13 errors),
# while the closest available approximation of the newer API reports 97:
#   pip install "cwapi3d==32.443.10" && mypy .
# Those 84 extra errors name the functions renamed or removed since v30 --
# add_wall_section_x/y, export_2d_wireframe, get_roof_surfaces,
# calculate_roof_area -- so they are a migration checklist, not noise, for
# anyone moving to 2026. Confirm against the API the running Cadwork actually
# exposes before acting on them.
cwapi3d>=30,<31

# Only needed by `python main.py --transport http`, a code path that calls
# mcp.app and does not currently work.
uvicorn>=0.34.0

# Development. mypy.ini targets Python 3.12; the tests need nothing extra,
# they run on the standard library.
mypy>=1.19
